 1. VISIÓN DEL PRODUCTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OLTVI es una plataforma de transporte de pasajeros para el mercado argentino que
compite directamente con Uber y DiDi. Su diferenciador central es una orquesta
de 8 agentes de Inteligencia Artificial corriendo en paralelo sobre Gemini 2.0
Flash, más una experiencia visual de nivel AAA (gráficos de videojuego) sobre
Google Maps en modo 3D.

Propuesta de valor:
  • Matchmaking inteligente: el AI elige el conductor óptimo en < 2 segundos
  • Precio transparente: desglose visible de cada componente del costo
  • Seguridad activa: monitoreo de desvíos, paradas anómalas y velocidad en tiempo real
  • Copiloto para conductores: sugerencias de zonas calientes y gestión de ganancias
  • Soporte sin espera: "Olivi" resuelve el 90% de consultas sin intervención humana
  • Gráficos inmersivos: efectos de neon, partículas y mapas 3D en tiempo real

Mercado objetivo: Argentina (Buenos Aires como hub principal)
  • Moneda: ARS (pesos argentinos)
  • GPS fallback: -34.6037, -58.3816 (Microcentro, CABA)
  • Idioma: español rioplatense

 4. LA ORQUESTA DE 8 AGENTES IA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Todos los agentes heredan de BaseAgent que provee:
  • chat(userMessage, history): String  → 3 reintentos con backoff 1s/2s/4s
  • executeMock(input): String           → Respuesta estática si mockMode=true
  • GenerativeModel lazy init            → gemini-2.0-flash con system prompt

─────────────────────────────────────────────────────────────────────────────
 4.1  AgenteMatchmaker
─────────────────────────────────────────────────────────────────────────────
Rol:        Encontrar al conductor óptimo para cada viaje
Función:    encontrarMejorConductor(contexto, conductores) → ResultadoMatchmaking
Algoritmo:  score = rating×0.5 + (1/(distanciaKm+1))×0.5
            Ordena conductores, filtra incompatibles por tipo de servicio
System prompt: "Eres el sistema de matchmaking de OLTVI. Evalúa conductores
               disponibles según distancia (30%), calificación (25%),
               tasa de aceptación (20%), tipo de servicio (15%), historial (10%)"
Salida:     ResultadoMatchmaking { conductor, eta, score, explicacion }

─────────────────────────────────────────────────────────────────────────────
 4.2  AgentePrecio
─────────────────────────────────────────────────────────────────────────────
Rol:        Calcular el precio justo y transparente del viaje
Función:    calcularPrecio(origen, destino, tipo, nivel, idUsuario) → ResultadoPrecio
Fórmula:    base=800 ARS + distanciaKm×350 ARS × multiplicadorNivel × factorDemanda
Niveles:    ESTANDAR×1.0, EXPRES×1.3, ESPECIAL×1.8
System prompt: "Calcula precios justos y transparentes. Muestra desglose visible:
               base + distancia + demanda + descuento. Sin precios sorpresa."
Salida:     ResultadoPrecio { total, desglose, precioBase, distanciaKm, factorDemanda,
                              descuento, explicacionAI }

─────────────────────────────────────────────────────────────────────────────
 4.3  AgenteSeguridad
─────────────────────────────────────────────────────────────────────────────
Rol:        Monitor de seguridad en tiempo real durante el viaje
Función:    monitorearViaje(contexto, posicionActual) → AlertaSeguridad?
Triggers:   desvío > 500m de ruta, parada > 3 min en zona no esperada,
            velocidad > 120 km/h, comportamiento anómalo
System prompt: "Eres el guardián de seguridad de OLTVI. Analiza cada posición GPS
               en tiempo real. Emite alertas solo cuando hay riesgo real."
Salida:     AlertaSeguridad? { severidad, mensaje, posicion, accionRecomendada }
            null si no hay riesgo

─────────────────────────────────────────────────────────────────────────────
 4.4  AgenteRuta
─────────────────────────────────────────────────────────────────────────────
Rol:        Optimización de ruta con tráfico, clima y alternativas
Función:    optimizarRuta(origen, destino) → RutaOptimizada
Considera:  tráfico en tiempo real, obras, eventos, condición climática
System prompt: "Optimiza rutas para Buenos Aires. Prioriza tiempo sobre distancia.
               Sugiere alternativas si hay congestión > 20% de demora."
Salida:     RutaOptimizada { puntos, distanciaKm, tiempoMinutos, alternativas,
                             advertencias, polyline }

─────────────────────────────────────────────────────────────────────────────
 4.5  AgenteSoporte ("Olivi")
─────────────────────────────────────────────────────────────────────────────
Rol:        Asistente de soporte conversacional 24/7
Función:    resolverConsulta(idUsuario, mensaje, contexto?) → MensajeChat
Capacidades: cancelación, reembolso, reclamos, preguntas frecuentes,
             escalado a humano si score_confianza < 0.6
System prompt: "Eres Olivi, la asistente de OLTVI. Amable, directa, rioplatense.
               Resuelve el 90% de problemas sin escalar. Si no podés, derivá
               calurosamente a soporte humano. Nunca digas 'no puedo'."
Salida:     MensajeChat { contenido, tipo, timestamp, opciones, accionRequerida }

─────────────────────────────────────────────────────────────────────────────
 4.6  AgenteFraude
─────────────────────────────────────────────────────────────────────────────
Rol:        Detección y prevención de fraude en transacciones
Función:    analizarTransaccion(idViaje, idUsuario, monto) → FraudeResultado
Detecta:    viajes fantasma, fraude de pago, cuenta tomada, colusión conductor-pasajero
Score:      0-100 (0=seguro, >70=bloqueo automático, 40-70=revisión manual)
System prompt: "Eres el sistema antifraude de OLTVI. Analiza cada transacción
               buscando patrones anómalos. Falsos positivos cuestan usuarios;
               falsos negativos cuestan dinero. Equilibra ambos riesgos."
Salida:     FraudeResultado { esFraude, scorRiesgo, tipo, accion, evidencia }

─────────────────────────────────────────────────────────────────────────────
 4.7  AgenteCopiloto
─────────────────────────────────────────────────────────────────────────────
Rol:        Coach de ganancias para conductores
Función:    obtenerSugerencia(idConductor, posicion, gananciasHoy) → SugerenciaCopiloto
Zonas hot:  Palermo, Recoleta, Microcentro, Puerto Madero, Palermo Hollywood,
            Villa Crespo, Belgrano, San Telmo
System prompt: "Eres el copiloto de un conductor de OLTVI en Buenos Aires.
               Sugiere zonas con alta demanda, horarios óptimos, y cuándo
               tomar un descanso. Prioriza el bienestar y las ganancias."
Salida:     SugerenciaCopiloto { zona, razon, gananciasEstimadas, distancia,
                                  prioridad, mensaje }

─────────────────────────────────────────────────────────────────────────────
 4.8  AgenteOperaciones
─────────────────────────────────────────────────────────────────────────────
Rol:        Inteligencia predictiva para el panel de administración
Función:    generarInsight(tipo: TipoInsight) → InsightOperaciones
Tipos:      DEMANDA_PREDICHA, CONDUCTORES_ESCASOS, INGRESOS_ANOMALIA,
            ZONA_RIESGO, OPTIMIZACION_FLOTA
System prompt: "Eres el cerebro analítico de OLTVI Operations. Analiza patrones
               históricos y predice demanda, escasez de conductores y anomalías.
               Genera insights accionables, no reportes descriptivos."
Salida:     InsightOperaciones { tipo, titulo, descripcion, impacto, acciones,
                                  timestamp, prioridad }

 5.1  FLUJO PASAJERO (app-usuario)
─────────────────────────────────────────────────────────────────────────────

 LOGIN
   → Ingresa número de teléfono (+54 9 ...)
   → [Firebase Auth] envía SMS con código OTP de 6 dígitos
   → Ingresa código → verificado → navega a SPLASH

 SPLASH (2.5s)
   → ParticleField como fondo
   → Logo OLTVI con animación fade-in + scale
   → Tagline: "Tu ruta, nuestra inteligencia"
   → Auto-navega a HOME

 HOME (pantalla principal)
   → Google Maps en modo 3D (tilt 30°, dark style personalizado)
   → PulseRing animado en posición del usuario
   → Marcadores de conductores disponibles con ETAs
   → Barra de búsqueda flotante (glass) en la parte superior
   → Panel inferior: "¿A dónde vas?" + destinos recientes
   → Botón flotante inferior: chat con Olivi

 BOOKING (al tocar la barra de búsqueda)
   → Campo de destino con autocompletado
   → Agentes en paralelo (OltviOrchestrator.procesarSolicitudViaje):
       • AgenteMatchmaker → mejor conductor disponible
       • AgentePrecio     → precio con desglose
       • AgenteRuta       → ruta optimizada
   → Card del conductor asignado (foto, rating, ETA, vehículo)
   → Desglose de precio con explicación AI
   → Selector de tipo de servicio (Estándar / Exprés / Especial)
   → Botón "Confirmar viaje" → ConfettiExplosion

 TRACKING (durante el viaje)
   → Mapa con conductor moviéndose hacia el pasajero
   → Neon polyline marcando la ruta
   → Contador de ETA con animación de pulso
   → Card inferior: conductor, calificación, vehículo
   → Badge de seguridad (AgenteSeguridad en tiempo real)
   → Botones: Cancelar (glass) / SOS (rojo)

 CHAT (soporte con Olivi)
   → Interface conversacional con "Olivi"
   → WaveformAnimation mientras procesa respuesta
   → Burbujas: glass para Olivi, naranja para usuario
   → Chips de acción rápida: Cancelar viaje, Reportar, Ver factura
   → Respuestas via OltviOrchestrator.atenderSoporte()

 PAGOS
   → Historial de viajes y montos
   → Gestión de medios de pago (preparado para MercadoPago)
   → Códigos promocionales

 PERFIL
   → Avatar + nombre + nivel (Nuevo/Regular/VIP/Premium)
   → Puntos acumulados + calificación promedio
   → Configuración de la cuenta

 5.2  FLUJO CONDUCTOR (app-conductor)
─────────────────────────────────────────────────────────────────────────────

 LOGIN

 OPERACIÓN (viaje activo)

 PERFIL DEL CONDUCTOR

   → Card del vehículo: modelo, color, tipo, patente
   → Estado de documentos: VTV, seguro, licencia (OK/Vencido)

 6. EFECTOS GRÁFICOS (GameEffects.kt)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

 1. PulseRing
    Dónde: marcador de posición del usuario en el mapa (HomeScreen)
    Cómo: InfiniteTransition con 3 anillos concéntricos, cada uno con delay escalonado.
          Canvas drawCircle con alpha y radius animados. Desaparecen al expandirse.

 2. ParticleField
    Dónde: SplashScreen y LoginScreen como fondo
    Cómo: 80 partículas con velocidades y posiciones iniciales aleatorias (random seed fijo).
          withFrameMillis loop actualiza posiciones. Canvas drawCircle con radio 2-4dp.
          Conecta partículas cercanas con líneas alpha bajas.

 3. NeonGlow (Modifier.neonGlow)
    Dónde: botón online/offline del conductor, avatar del perfil, OltviButton
    Cómo: Modifier.drawBehind con BlurMaskFilter(blurRadius, SOLID).
          Dibuja el mismo shape del componente con el color de neon.
          Layer con hardware acceleration requerido.

 4. GlassCard
    Dónde: prácticamente en todos los cards de la app
    Cómo: Box con background semi-transparente (Color(0xFF1A2733) + 0.85 alpha)
          más borde de 1dp con gradiente naranja semi-transparente.
          RoundedCornerShape(16.dp). Eleva contenido via BoxScope.

 5. WaveformAnimation
    Dónde: ChatScreen mientras Olivi procesa la respuesta
    Cómo: 12 barras verticales con InfiniteTransition animando la altura.
          Cada barra tiene phase offset distinto (π/6 per bar).
          Color naranja (OltviColors.action) con cornerRadius.

 6. ShimmerEffect (Modifier.shimmer)
    Dónde: estados de carga en DashboardScreen y GananciasScreen
    Cómo: Modifier.drawWithContent con Brush.linearGradient sweeping de izq a der.
          InfiniteTransition mueve el gradiente con offset repetido.
          Overlay sobre el contenido real.

 7. ConfettiExplosion
    Dónde: confirmación de viaje en BookingSheet, completar viaje en OperacionScreen
    Cómo: 40 partículas desde el punto de toque (center: Offset).
          Cada partícula tiene velocidad angular y lineal aleatoria.
          LaunchedEffect de 2 segundos, luego llama onDone().
          Canvas en fullscreen overlay transparente.

REGLA DE ORO: Las claves NUNCA se commitean al repositorio.

Flujo de claves para desarrollo local:
  1. android/local.properties (gitignored):
     MAPS_API_KEY=AIzaSy...
     GEMINI_API_KEY=AIzaSy...
  2. Gradle lee local.properties via project.findProperty()
  3. Inyecta en BuildConfig.MAPS_API_KEY y BuildConfig.GEMINI_API_KEY
  4. Android Manifest recibe MAPS_API_KEY via manifestPlaceholders
  5. AppModule (por app) expone BuildConfig.GEMINI_API_KEY via @Named("geminiKey")
  6. CoreModule recibe la clave y la pasa a los 8 agentes
  7. Si clave vacía → mockMode=true automáticamente

Flujo de claves para CI/CD (GitHub Actions):
  1. Secrets en el repo: MAPS_API_KEY, GEMINI_API_KEY
  2. Workflow inyecta: echo "MAPS_API_KEY=${{ secrets.MAPS_API_KEY }}" >> local.properties
  3. Gradle build los toma igual que en desarrollo local

Archivos en .gitignore relevantes:
  android/local.properties
  **/google-services.json
  **/*.keystore
  **/*.jks
  android/.idea/
  android/*/build/

RESPUESTA A LA PREGUNTA "¿USAMOS FIREBASE?": SÍ, RECOMENDADO.

Estado actual (v1.0):
  ✅ Firebase BOM 33.1.2 en todas las apps
  ✅ google.services plugin declarado en app-conductor y app-jefe
  ✅ Dependencias firebase-auth, firebase-firestore, firebase-messaging en deps
  ⏳ google-services.json pendiente (el usuario debe generarlo)
  ⏳ Pantallas de login preparadas (OTP UI lista, backend mock)

Para activar Firebase completamente:
  1. Ir a Firebase Console → console.firebase.google.com
  2. Crear proyecto "OLTVI" (o vincular al proyecto de Google Cloud existente)
  3. Agregar 3 apps Android:
     • com.oltvi.usuario  → descargar google-services.json → android/app-usuario/
     • com.oltvi.conductor → descargar google-services.json → android/app-conductor/
     • com.oltvi.jefe     → descargar google-services.json → android/app-jefe/
  4. Activar en Firebase Console:
     • Authentication → Phone number (para OTP)
     • Authentication → Email/Password (para admin)
     • Cloud Firestore → Create database (modo test para empezar)
     • Cloud Messaging → activado por defecto
  5. Descomentar en app-usuario/build.gradle.kts:
     alias(libs.plugins.google.services)

Esquema de Firestore propuesto:
  /users/{userId}           → datos del usuario, nivel, puntos
  /conductores/{id}         → perfil, vehiculo, posicion, online, rating
  /servicios/{id}           → estado en tiempo real del viaje
  /eventos_viales/{id}      → incidentes activos
  /insights/{id}            → insights generados por AgenteOperaciones

Tipos de notificaciones FCM:
  NUEVA_SOLICITUD           → conductor recibe viaje disponible
  CONDUCTOR_ASIGNADO        → pasajero recibe confirmación
  CONDUCTOR_CERCA           → "Tu conductor llega en 2 minutos"
  VIAJE_INICIADO            → ambos reciben
  VIAJE_COMPLETADO          → con calificación pendiente
  ALERTA_SEGURIDAD          → pasajero + ops si AgenteSeguridad detecta riesgo
  INSIGHT_CRITICO           → admins si hay escasez o anomalía de ingresos
